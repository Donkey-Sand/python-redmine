## 三、你从明天开始要做的事情

顺序非常重要。

### 第一步：整理正式环境用的SQL/DDL

以DEV环境中已经完成的表和View为基础，制作正式环境使用的DDL。

DDL中必须补充：

* 表的注释
* 字段的注释
* 表的逻辑名
* 字段的逻辑名
* 各字段、分类值的含义

例如：

* `alert_type`表示什么
* 数值`1`、`2`分别表示什么
* 新规告警和持续告警如何区分

DEV环境只是试验环境，所以之前没有完整填写这些内容没关系；但正式环境使用的DDL必须整理规范。

### 第二步：整理View中的字段

对方认为目前View里带入了一些已经完全不使用的字段，可以考虑删除。

会议中提到可能不需要的字段包括：

* `register_time`或类似的登记时间字段
* `receive_time`
* `route2`
* `error_detail`
* 其他完全没有用于计算或画面展示的字段

但是会议录音中的字段名识别可能不完全准确，实际应以你当前SQL中的名称为准。

需要保留的内容包括：

* 日期相关字段
* 月、周、日等统计粒度字段
* Error Code
* Error Type
* Count
* `is_alert`
* `alert_type`
* `route1`等实际参与计算的字段
* 计算使用的参数
* 为保留计算历史而需要记录的字段

其中：

* `is_alert`仍然需要。
* `alert_type`也需要，用于区分“新规告警/持续告警”，后续可能还会影响背景颜色。
* 当前结果表已经接近最小结构，基本不需要继续删。
* 参数和计算条件相关的历史表建议保持原样，因为将来需要追溯“当时使用了什么参数进行计算”。
