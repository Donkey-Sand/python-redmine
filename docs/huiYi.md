会议中关于QuickSight过滤器的讨论非常关键。对方认为：你当前设计中的不良率是提前在DB表里计算好的，但如果QuickSight使用过滤器，分子和不良率都会变化，因此固定的不良率结果可能无法使用。

## 1. QuickSight需要哪些过滤器

会议中明确提到或暗示需要按照这些维度筛选：

* 机种
* Gas Type
* Error Code
* 月份

其中对方举的主要例子是机种和Error Code：

> この機種でフィルターかけたら、この機種やったらこんだけの不良率になる。
> 使用某个机种进行筛选后，需要显示该机种对应的不良率。

> エラーコード全部やったら1000件かもしれないけど、このエラーだけにしたら100件になる。
> 所有错误代码可能有1000件，但只筛选某个错误代码后可能只有100件。

也就是说，QuickSight画面不是只展示固定的全量数据，而是要求用户选择条件后，页面数值跟着变化。

## 2. 对方指出你当前方案的问题

你当前准备的是：

* 在DB侧计算分子；
* 在DB侧计算分母；
* 在结果表中提前计算不良率；
* QuickSight读取最终结果。

但对方认为，如果在QuickSight中筛选机种或错误代码：

* 分子会从1000件变成100件；
* 分母也可能因为机种等条件发生变化；
* 不良率自然也应该重新计算。

因此，对方说：

> ここで割り算をしたところで、画面上でフィルターをかけて分子の数が変わったら、不良率も変わりますよね。

意思是：

> 即使在DB表中已经完成除法，画面使用过滤器后分子数量发生变化，不良率也应该随之变化。

随后又明确指出：

> このテーブルとして計算を持っている意味はあまりない。というか、意味がない。

意思是：

> 把预先计算好的不良率保存在结果表中，基本没有意义。

## 3. 对方倾向的处理方式

会议中的倾向是：

* DB或中间表保存基础数据；
* 至少保留分子和分母计算所需的数据；
* QuickSight根据筛选后的数据动态计算不良率。

大致可以理解为：

[
QuickSight动态不良率
===============

\frac{过滤后的错误件数}{过滤条件所对应的连接台数}
]

而不是直接使用DB中提前算好的固定值。

对方原话是：

> 最終的な計算はQSの画面でやってもらわんとあかんのちゃうかな。

即：

> 最终计算可能必须交给QuickSight画面动态完成。

不过这仍然是会议中的设计方向，还没有完全确定具体实现方式。

## 4. 分子如何响应过滤器

分子来自错误历史表或告警中间表中的错误记录／`count_judgement`。

如果用户筛选：

* 某个机种；
* 某种Gas Type；
* 某个Error Code；
* 某个月份；

QuickSight就应该只汇总满足条件的数据。

例如：

```text
全部Error Code：分子1000
筛选Error Code A：分子100
筛选机种X＋Error Code A：分子30
```

所以分子数据不能只保留已经按月份汇总后的总数，还必须包含支持过滤的维度，例如：

* 月份
* 机种
* Gas Type
* Error Code
* 错误件数／`count_judgement`

否则QuickSight无法按条件重新汇总。

## 5. 分母如何响应过滤器

分母比起来更复杂。

会议提到，NW连接台数可能需要按以下维度准备：

* 月份
* 机种
* Gas Type

但Error Code通常属于错误事件，不属于设备连接信息，所以分母是否应该随Error Code筛选变化，需要特别注意。

一般来说，如果筛选Error Code：

* 分子会变化；
* 分母仍应是该月、该机种、该Gas Type对应的连接台数；
* 不应该因为选择某个Error Code就减少连接台数。

因此不能简单地把分母复制到每条Error Code记录后再直接SUM，否则会重复累计分母。

会议中没有把这一点完全确定下来，但对方已经意识到“如何在QuickSight中得到正确且不重复的分母”是需要你继续设计的问题。

## 6. 过滤器也会影响背景色

会议中还要求某个月发生错误时，画面背景色发生变化。

使用过滤器后，颜色也应该与筛选结果一致。例如：

* 全部机种下，2021年3月存在错误，所以变色；
* 筛选机种A后，如果3月份机种A没有错误，则不应该继续变色；
* 筛选机种B后，如果3月份机种B存在错误，则应该变色。

因此颜色判断字段或逻辑也必须具备相应维度，不能只保存一个全局性的月份Flag。

可以考虑基于筛选后的错误件数判断：

```text
筛选后错误件数 > 0 → 变色
筛选后错误件数 = 0 → 不变色
```

或者基于筛选后的 `is_alert` 判断，但需确认需求是“发生错误就变色”还是“达到告警条件才变色”。

## 7. 会议对你的最终要求

对方没有直接指定你必须写某一个QuickSight公式，而是要求你重新考虑：

* DB应该准备哪些粒度的数据；
* 是否使用历史表／告警中间表；
* 是否需要新建View或中间表；
* 哪些值在DB中计算；
* 哪些值在QuickSight中计算；
* 过滤机种、Gas Type、Error Code后，分子、分母、不良率和颜色是否都正确；
* 形成方案后再向他们共享。

简而言之：会议认为不良率不能只在DB里提前算死。因为QuickSight存在筛选器，必须保存足够细粒度的分子、分母和告警数据，并在QuickSight中根据筛选结果动态汇总、计算不良率及控制颜色。
